# 空壳布局方案开发时间粗估

> 已归档：本文只作历史估算和预期管理材料，不作为当前计划入口。当前唯一 PlanMD / 主计划是根目录 `CORE_RESTRUCTURE_PLAN.md`。

最后更新：2026-05-25

## 0. 用途声明

本文只用于粗略估算“实现类似截图中 CAD 平面方案生成能力”的开发阶段和时间成本，帮助做心理预期和资源安排。

本文不是系统开发规范，不是正式实施计划，也不是 Core 架构文档。后续开发仍应以 `README.md`、`CORE_STATUS.md`、`CORE_ROADMAP.md`、`CORE_RESTRUCTURE_PLAN.md` 和 `SHELL_LAYOUT_FOUNDATION_DESIGN.md` 为准。

本文讨论的目标只包含 CAD 平面方案本体，不包含 PPT 标注、红色说明箭头、汇报排版、渲染包装等内容。

复盘更新：截至 2026-05-25，本文中“Core 基础模型和协议”“半自动空壳输入闭环”“动线与功能区算法”“参数化家具 / 对象布置”的一部分，已经以 Phase P-V 的形式落入主计划并形成非 CAD prototype。本文保留为历史估算和预期管理材料，不作为当前开发进度来源；当前进度以 `CORE_STATUS.md` 和 `CAD_AGENT_STATUS.md` 为准，下一阶段执行计划以 `CORE_RESTRUCTURE_PLAN.md` 为准。

## 1. 总体判断

截图中的方案能力，本质不是一个小功能，而是一条 Core 级产品线：

```text
空壳图纸理解
-> 项目约束
-> 动线生成
-> 功能区切分
-> 家具/图块布置
-> CAD 预览落图
-> 验证与修正
-> 公司场景精细化
```

在当前仓库状态下，很多 Core 能力还没有实现，因此不建议直接冲“全自动生成最终方案”。更现实的路线是：

```text
先做半自动 MVP
再做验证闭环
再接真实样本
再逐步增强自动识别和公司业务偏好
```

粗略时间判断：

| 目标级别 | 大致时间 | 结果形态 |
| --- | --- | --- |
| 可演示 MVP | 4-8 周 | 半自动输入空壳，自动生成动线、功能区和基础家具预览 |
| 内部辅助出方案 | 3-6 个月 | 可用于设计师快速出草案，需要人工审核和调整 |
| 稳定承接一部分业务量 | 6-12 个月 | 能处理较多真实图纸，有公司图库、评分、纠错和验证闭环 |

## 2. 阶段拆解

### 阶段 1：Core 基础模型和协议

预计时间：3-7 天

目标：

先把数据结构立起来，不急着做智能布局。

主要内容：

- `SHELL_MODEL`
- `PROJECT_MODEL`
- `CIRCULATION_MODEL`
- `FUNCTION_ZONE`
- `OBJECT_SPEC`
- `BLOCK_LIBRARY`
- `LAYOUT_PROPOSAL`
- `VERIFICATION_REPORT`

预期结果：

- 有 schema。
- 有 example。
- 能 validate。
- 能被后续模块稳定引用。

风险：

- 如果不先做协议，后续容易变成散装 JSON 和脚本互相传参。
- 如果协议过早绑定公司场景，后面家装、办公、餐饮等场景会难以复用。

### 阶段 2：半自动空壳输入闭环

预计时间：1-2 周

目标：

先不依赖自动读图，允许通过人工标注或结构化 JSON 输入外轮廓、入口、柱子、消防门、卷帘、不可布置区。

主要内容：

- 人工标注 JSON。
- 空壳边界读取。
- 可布置区计算。
- 不可布置区扣除。
- 基础可视化落图到 `CODEX_PREVIEW`。

预期结果：

- 系统能“理解”一个空壳空间。
- 能把边界、入口、柱子、不可布置区画出来。
- 可以绕开早期 DWG 自动识别难题，让布局能力先跑起来。

风险：

- 如果第一版强依赖自动读图，会卡在复杂 DWG 识别上。
- 如果没有人工补充路径，真实项目稍微不规范就无法继续。

### 阶段 3：动线与功能区算法

预计时间：2-4 周

目标：

生成截图方案中最核心的空间骨架：动线和动线两侧功能区。

主要内容：

- 主入口到关键出口或空间深处的主动线。
- 直线、L 型、环形、沿边等候选动线。
- 通道宽度 buffer。
- 动线两侧区域切分。
- 功能区候选生成。
- 柱子、消防门、门洞避让。
- 基础评分。

预期结果：

- 能生成“像那么回事”的平面骨架。
- 至少能输出 1 个合理方案。
- 最好能输出 2-3 个候选方案。

风险：

- 这一步不要让 LLM 直接猜坐标。
- 坐标、碰撞、通道宽度、避让必须走确定性几何算法。

### 阶段 4：参数化家具 / 对象布置

预计时间：2-4 周

目标：

在没有公司图库的情况下，先通过参数化对象生成可看的家具布置。

主要内容：

- 基础对象：床、桌、椅、柜、沙发、货架、餐桌、前台等。
- 对象尺寸。
- 朝向规则。
- 贴墙规则。
- 前方操作空间。
- 对象碰撞检测。
- 基于功能区自动摆放。
- 转成 `CAD_PLAN`。

预期结果：

- 从“空壳 + 动线 + 功能区”变成“有家具/对象的平面草案”。
- 不依赖真实图库也能先看到布局效果。

风险：

- 参数化对象不要做成公司专用。
- 真实图库可以后补，不应成为第一版阻塞项。

### 阶段 5：预览落图与验证闭环

预计时间：1-3 周

目标：

让结果可信，而不是只生成一堆 JSON。

主要内容：

- 扩展 `CAD_PLAN` 支持多对象、多图层、多段线、区域、块或对象。
- dry-run 能清楚展示所有对象和坐标。
- `CODEX_PREVIEW` 批量落图。
- 截图。
- 实体回读。
- 对比预期尺寸、图层、数量、位置。
- 生成 `VERIFICATION_REPORT`。

预期结果：

- 系统进入“可验收”状态。
- 能区分：
  - 已生成方案。
  - 已 dry-run。
  - 已执行落图。
  - 已截图。
  - 已几何验证。

风险：

- 只看到截图不能等于几何准确。
- AutoCAD / CAD-MCP 环境不稳定会影响这阶段节奏。

### 阶段 6：DWG 自动识别增强

预计时间：3-8 周

目标：

从半自动走向更自动，减少人工标注。

主要内容：

- 读取 CAD 实体。
- 图层识别。
- 多段线 / 线段合并。
- 外轮廓候选识别。
- 柱子候选识别。
- 门洞、门块、消防门、卷帘识别。
- 文字辅助识别。
- 不确定点让用户确认。

预期结果：

- 对规范图纸能自动提取大部分空壳信息。
- 对不规范图纸能列出不确定点，而不是乱猜。

风险：

- 图纸规范程度会极大影响时间。
- 图层统一、块名统一、线条闭合程度好，会快很多。
- 图层乱、块名乱、线段碎，会慢很多。

### 阶段 7：公司业务场景精细化

预计时间：4-12 周

目标：

在通用 Core 之上，把截图这种公司平面方案风格做成一个场景能力。

主要内容：

- 公司方案 Agent。
- 公司功能区偏好。
- 公司图库或参数化对象风格。
- 动线两侧功能组织逻辑。
- 常见户型策略。
- 多方案推荐。
- 方案说明。
- 出图风格接近公司习惯。
- 用真实项目样本反复调权重。

预期结果：

- 更接近公司实际出图习惯。
- 能服务一部分内部业务量。
- 设计师主要做审核、调整和最终把控。

风险：

- 这一步不要提前做。
- 如果 Core 还没稳定就深度开发公司场景，会把通用底座写偏。

## 3. 推荐推进节奏

### 第一个月

重点：

- Core 基础模型。
- 半自动空壳输入。
- 主动线生成。
- 功能区切分。
- 简单参数化家具。

目标：

先看到一个能跑通的半自动方案原型。

### 第二个月

重点：

- 预览落图。
- 验证报告。
- 多方案评分。
- 碰撞和通道检查。

目标：

让原型从“能生成”变成“能检查、能解释、能验收”。

### 第三个月

重点：

- 接真实样本。
- 引入公司场景 Agent 的早期偏好。
- 调整功能区和家具布置策略。

目标：

开始接近公司内部辅助出方案的状态。

### 第四个月以后

重点：

- DWG 自动识别增强。
- 公司图库沉淀。
- 更多真实项目测试。
- 方案质量和稳定性迭代。

目标：

逐步减少人工输入，提高真实项目覆盖率。

## 4. 优先级建议

推荐顺序：

1. 模型协议。
2. 半自动空壳输入。
3. 动线算法。
4. 功能区切分。
5. 参数化对象。
6. `CAD_PLAN` 扩展和落图验证。
7. 公司场景偏好。
8. DWG 自动识别增强。
9. 真实图库精细化。

不建议顺序：

```text
先做公司专用方案
-> 再补 Core
-> 再补读图
-> 再补验证
```

这样很容易形成能演示但难复用的脚本堆。

## 5. 时间影响因素

会让时间变短的因素：

- 图纸图层规范。
- 门、柱、消防设施有统一块名或图层。
- 公司接受第一版半自动输入。
- 先用参数化家具，不强求真实图库。
- CAD 环境稳定。
- 每阶段都有清晰验收样本。

会让时间变长的因素：

- 一开始要求全自动识别任意 DWG。
- 一开始要求接近最终施工图。
- 图库块没有标准。
- 每个真实项目图纸规范差异很大。
- 频繁修改 Core / Agent 边界。
- 没有截图和实体回读验证。

## 6. 粗略人力预期

如果由 Codex 持续开发、用户持续验收：

```text
4-8 周：可演示 MVP
3-6 个月：内部辅助方案工具
6-12 个月：可较稳定承接一部分真实业务量
```

如果希望更快进入可见成果，建议把第一版目标压缩为：

```text
人工标注空壳
-> 自动动线
-> 自动分区
-> 参数化家具
-> CODEX_PREVIEW 预览
```

不要第一版就要求：

```text
自动读懂所有 DWG
-> 自动完成公司风格最终方案
-> 自动生成正式施工图
```

## 7. 结论

这个方向是可行的，但它不是一个小功能，而是 CAD-Agent 的核心产品线之一。

边界控得好，先做半自动 MVP，时间可控；一开始追求全自动读图、最终级方案和公司风格精细化，时间会快速膨胀。

最稳路线：

```text
先跑通半自动设计引擎
再补验证
再接真实样本
再做公司场景精细化
最后逐步增强自动识别和图库
```
