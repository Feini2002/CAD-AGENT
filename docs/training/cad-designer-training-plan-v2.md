# CAD Designer Agent 训练计划 V2

最后更新：2026-06-01

本文记录正式训练前的 **V2 训练地图扩容**。它不是表 C registry，也不是施工图能力声明；它是 `CAD Designer Agent` 在后续训练中要逐步完成的课程地图。

## 一句话

V2 保留训练工作台现有分类，但把每个分类从少量对象扩成设计师成长路径里的训练簇：先补 CAD 生产卫生，再补对象符号语法，再进入房间组合、图纸表达和交付自检。

## 调研来源边界

V2 参考了四类真实来源：

- 职业与岗位要求：室内设计师、CAD 绘图员、家装设计师、FF&E / 家具配置角色普遍要求 AutoCAD、施工图、空间规划、家具与 FF&E、厨卫柜体、标注表格和协作审图。
- 教育与认证路径：CIDA / NCIDQ、院校课程和 AutoCAD 课程普遍从 drafting、space planning、FF&E、construction documents、codes、professional practice 逐步展开。
- 家装交付链路：真实室内施工图通常包含量房 / 现状、拆改、新建、平面、地面、顶面、灯具、电气、给排水、立面、节点、大样和材料 / 设备 / 柜体表。
- 对象库与人体工学：住宅对象训练应覆盖外包络、使用净空、门 / 抽屉 / 翻板开启域、朝向语义、组合关系、标注语义和碰撞 / 通行检查。

这些来源只证明“训练地图应该覆盖什么”；每一项是否会画，仍要靠具体训练轮次里的结构化意图、`CAD_PLAN`、validate、dry-run、`CODEX_PREVIEW`、created handles 回读、审计和用户反馈。

## 工作台体量

V2 结构化数据由 `scripts/build_capability_map_data.py` 生成，并同步到 `capability-map-data.js`。

| 分类 | V2 后训练项数量 | 训练重点 |
| --- | ---: | --- |
| CAD 基础操作 | 31 | 图元、选择、编辑、变换、图层、块（block 命令 / 引用机制，不等于标准图块资产）、layout、plot、红线、回读和图纸卫生 |
| 基础家具 | 46 | 坐、卧、吃、工作、会客等家具对象的部件、尺度、朝向、组合和净空 |
| 储位家具 | 29 | 衣柜、书柜、鞋柜、厨柜、浴室柜、转角 / 拉篮等柜体模数与开启域 |
| 厨卫对象 | 36 | 水槽、灶具、冰箱、洗碗机、洁具、淋浴、浴缸、厨卫净空和工作三角 |
| 基础绘图 | 43 | 现状、拆改、新建、平面、地面、顶面、灯具、电气、给排水、立面和节点 |
| 标注表达 | 32 | 尺寸链、编号、图例、索引、标题栏、材料 / 设备 / 柜体 / FF&E 表和 checked/not_checked |

合计：217 个训练计划项。

## 训练推进逻辑

| 阶段 | 主目标 | 训练方式 |
| --- | --- | --- |
| 基础生产卫生 | CAD 生产卫生 | 选择 L0 / L1 项，训练图层、图元、编辑、块（block 命令 / 引用机制）、hatch、layout、plot、回读和图纸清理 |
| 对象符号语法 | 对象符号语法 | 选择基础家具、储位家具、厨卫对象，训练部件、尺度、朝向、组合、标注和碰撞 |
| 房间平面组合 | 房间平面组合 | 选择玄关、客餐厅、卧室、厨房、卫生间、阳台等组合任务，训练通道、开门、家具归属和净距 |
| 专业表达闭环 | 专业表达和交付闭环 | 选择小套图、立面、节点、表格和 checked/not_checked，训练图纸间一致性和用户验收提示 |

训练时每轮仍只推进 1 个基础课程、1 个对象 / 图纸训练项，或 1 条 feedback 关闭项；V2 只是让正式训练前的地图足够厚，不要求一次训练多个对象。

## 训练批次依赖图

V2.1 把 217 项拆成训练批次。批次只描述先后关系、前置依赖和验收证据，不绑定训练天数，也不要求一轮训练完成整批。

| 批次 | 前置 | 训练目标 | 绑定验收器骨架 |
| --- | --- | --- | --- |
| 基础生产卫生 | 无 | 基础图元、坐标、捕捉、闭合、handles / bbox 回读 | 闭合几何、回读证据 |
| 安全编辑与图层纪律 | 基础生产卫生 | 选择、变换、偏移修剪、图层隔离、失败回滚 | CODEX_PREVIEW 图层安全、闭合几何、回读证据 |
| 高频家具符号 | 安全编辑与图层纪律 | 床、沙发、餐桌椅、书桌和电视柜的部件、方向和净距 | 净距碰撞、开启域、回读证据 |
| 储位厨卫对象 | 高频家具符号 | 柜体、厨房设备、洁具、工作三角和人体净空 | 净距碰撞、开启域、厨房工作三角 |
| 房间平面组合 | 储位厨卫对象 | 量房、原始结构、门窗洞口、房间闭合轮廓和家具归属 | 闭合几何、净距碰撞、开启域 |
| 图纸表达与局部套图 | 房间平面组合 | 拆改、新建、地面、顶面、灯具、电气、立面和节点表达 | 尺寸链、跨图一致性、回读证据 |
| 标注表格与低噪声交付 | 图纸表达与局部套图 | 尺寸链、编号、图例、材料表、FF&E 表和 checked / not_checked | 尺寸链、表格数量、checked / not_checked |
| 跨图纸交付闭环 | 标注表格与低噪声交付 | 平面、立面、索引、门窗表、柜体表、材料表和图纸目录对账 | 跨图一致性、表格数量、checked / not_checked |

结构化字段写在 `capability-map-data.js` 的 `trainingBatches`，由 `scripts/build_capability_map_data.py` 生成。`scripts/run_training_workbench_agent_check.py` 会检查批次引用的训练项、前置批次和验收器 id 是否存在。

## 机器验收器骨架

V2.1 只登记验收器骨架，目标是让后续训练知道“应该检查什么”。它们目前不是可执行 CAD 证明，不计入表 C。

| 骨架 | 用途 | 典型失败 |
| --- | --- | --- |
| CODEX_PREVIEW 图层安全 | 防止训练落图污染正式图层 | 写入正式图层、回滚后遗留对象 |
| 闭合几何与端点洁净 | 检查房间、多段线和修剪结果 | open endpoint、gap、重复共享边 |
| handles 回读证据完整性 | 检查是否有 created handles、bbox 和实体类型回读 | 只有截图、未说明 not_checked |
| 净距与碰撞 | 检查床侧、椅后、洁具前方和通道净空 | 通道不足、门扇侵入、家具碰撞 |
| 开门 / 抽屉 / 翻板开启域 | 检查门弧、抽屉拉出和柜门打开空间 | 衣柜门碰床、抽屉被挡 |
| 厨房工作三角 | 检查水槽、灶具、冰箱之间的路径关系 | 三角锚点缺失、路径被岛台阻断 |
| 尺寸链闭合 | 检查总尺寸、分段尺寸和对象 bbox | 分段和总尺寸不一致 |
| 跨图纸一致性 | 检查平面、立面、索引、表格之间互相引用 | 立面索引孤立、材料编号漏表 |
| 表格数量对账 | 检查 tag、schedule row 和数量字段 | FF&E 表漏项、编号重复 |
| checked / not_checked 汇报完整性 | 保证交付说清证明了什么、没证明什么 | 只堆数字、不提示用户看点 |

## 证据边界

- V2 训练项进入工作台，只表示“已经列入训练地图”。
- V2.1 批次依赖和验收器骨架只表示“后续训练知道先后关系和应检项”，不表示检查器已实现。
- `目标已声明`、`计划中`、`训练中` 和 `已沉淀` 都不等于表 C。
- CAD 基础操作类的图库 / 自产轨道默认是“不适用”：它不要求标准图块输入，也不把课程结果晋升为自产资产；通过证据来自结构化意图、validate / dry-run、`CODEX_PREVIEW`、handles / bbox / 端点回读和审计。
- 参考图库、外部资料、标准尺寸和人体工学锚点只算上游证据，不算 CAD 能力。
- 真实 CAD 声明必须继续走 `CAD_PLAN` / 结构化意图、validate、dry-run、`CODEX_PREVIEW`、created handles 回读、机器审计和必要截图。
- 用户案例通过以 `projects/<case>/feedback.md` 为准，不能被训练工作台状态替代。

## 下一批候选方向

V2 后下一批更适合做“训练质量”而不是继续只加对象：

1. 为高频对象建立参数化对象族 schema，例如床、沙发、餐桌椅、衣柜、橱柜、洁具。
2. 把验收器骨架晋升为可执行检查器，例如椅后净空、床侧通道、柜门开启、厨卫净空。
3. 为小套图建立跨图纸一致性审计，例如平面编号、立面索引、材料表、FF&E 表和图面数量一致。
4. 建立训练样本包：真实白话 brief、参考图、预期 intent、审计 checklist 和用户反馈模板。
