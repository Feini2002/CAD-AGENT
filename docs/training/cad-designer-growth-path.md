# CAD Designer Agent 成长路径

最后更新：2026-06-01

本文定义训练期的新目标模型：仓库继续是通用 CAD Agent Core Lab，但训练对象从“若干能力项并列推进”升级为 **CAD Designer Agent**，也就是一个从 CAD 基础课成长起来、会调用各类 Agent 和资产的电子设计师。

## 一句话

`CAD Designer Agent` 是总训练对象；家装、资产、视觉语义、需求拆解、执行、审计、修复和沉淀等 Agent 是它可调用的知识储备和流程能力。现有能力矩阵保留，但改为它的 **能力护照**。

## 为什么这样改

真实设计师不是先学“沙发方向语义”，而是先学点、线、矩形、选择、移动、旋转、偏移、修剪、图层、闭合、标注，再逐步进入对象符号、房间平面、专业表达和施工图。训练系统也应按这个成长路径建立能力，而不是只按对象清单补丁式推进。

## 成长阶段

| 阶段 | 名称 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| L0 | CAD 基础操作 | 图元、选择、编辑、变换、偏移、修剪、图层、闭合、回读 | active |
| L1 | 几何洁净与约束 | 端点、闭合、共享边、对齐、洞口、尺寸约束 | planned |
| L2 | 对象符号语法 | 家具、门窗、洁具等对象的部件和符号表达 | planned |
| L3 | 房间平面组合 | 墙体、门窗、家具、通道和朝向组合 | planned |
| L4 | 专业表达 | 标注、图层、文字、比例、线型和出图表达 | planned |
| L5 | 施工图表达 | 平面、立面、节点、详图、材料和说明 | future |
| L6 | 设计判断 | 方案比较、规范意识、用户偏好和设计取舍 | future |

## 第一阶段毕业目标

采用方案 C：**电子设计师雏形**。

它不是只会基础命令，也不是只会画家具；第一阶段要把三件事连起来：

1. 基础 CAD 操作能被结构化表达和回读。
2. 家装对象训练能复用基础操作，而不是直接跳对象补丁。
3. 审计和自检能说明 checked / not_checked，知道什么还没证明。

但第一批课程必须从方案 A 的基础能力开始铺开。

## 第一批课程

| 课程 | 训练焦点 | 通过边界 |
| --- | --- | --- |
| `cad-primitives` | 线、矩形、圆、圆弧、多段线 | 能从结构化意图生成基础图元并回读实体 |
| `cad-selection-edit` | 选择、移动、复制、删除 | 不误动正式图层或计划外对象 |
| `cad-transform` | 旋转、镜像、缩放 | 基点、方向和组合对象关系清楚 |
| `cad-offset-trim` | 偏移、修剪、延伸 | 修剪后无明显缺口、毛刺、重复边 |
| `cad-layer-discipline` | 图层、颜色、线型 | 默认只写 `CODEX_PREVIEW`，图层语义可审计 |
| `cad-closure-constraints` | 闭合、对齐、共享边 | 端点、bbox、gap / overlap / open endpoint 可检查 |
| `cad-readback-audit` | handles 回读、自检汇报 | 能说清机器证据证明了什么、没证明什么 |

V2 只是训练地图扩容：它不提升表 C，不代表已会施工图，也不替代任意用户案例的 `feedback.md` 验收。

## 复合任务与能力组合

成长路径训练的是可组合能力，不要求把所有组合都写入训练计划。真实使用中，用户可能把多个课程自然叠加，例如“看截图里的沙发并标注尺寸”“按参考图画茶几再加编号”“识别已有门洞并补开启方向”。这些任务应按已有能力护照动态编排，而不是把 V2 训练地图扩成无限排列组合。

复合任务处理原则：

1. 先拆解为已有阶段能力：截图 / 视觉识别、对象符号、尺度来源、标注表达、图层纪律、CAD 执行和审计。
2. 再声明证据来源：截图推断、用户给定尺寸、比例参照、DWG / handles 回读或原 `CAD_PLAN`。
3. 最后分别汇报 checked / not_checked：不能用视觉推断替代真实 CAD 几何证明。

只有当某类组合反复出现、能形成稳定验收器或暴露通用链路缺口时，才把它晋升为训练项、benchmark 或规则包。

## 回流复训

成长路径不是单向封存流程。L0 基础操作 31/31 通过后，表示这些项目已有一版训练证据和沉淀；后续 L2 / L3 / L4 复杂任务如果暴露基础命令、图层、闭合、回读、块引用、layout / plot 或安全回滚不扎实，必须回流到对应 L0 项做加强训练。

回流复训的最小闭环是：记录复杂任务触发点 → 映射到基础训练项 → 修改脚本、Prompt、检查器或规则 → 复训基础项 → 回测原复杂任务 → 追加新证据和 learning promotion。旧通过证据保留为历史，不把“已完成”解释成“永不再练”。

## Agent 关系

```text
CAD Designer Agent
  -> residential / future scene agents       场景知识
  -> pipeline_context_curator                上下文收束
  -> pipeline_asset_retriever                资产和常识检索
  -> pipeline_visual_intent / pipeline_intent 需求与视觉语义
  -> pipeline_execute                        CODEX_PREVIEW 落图
  -> pipeline_audit / pipeline_repair        审计与修复
  -> pipeline_delivery / learning_promoter   交付与沉淀
```

场景 Agent 仍保持轻量，不写通用算法；Core 仍负责执行、验证、审计和安全边界。

## 证据边界

- 成长路径进度不等于表 C。
- 基础课程通过不等于完整施工图能力。
- 基础课程通过也不等于永久封存；复杂任务发现基础薄弱时必须允许二次 / 多次复训。
- 复合任务可以临场组合已有能力；训练地图不穷举组合，单次组合通过也不自动新增课程项。
- 工作台训练状态不等于用户案例通过。
- 基础 CAD 操作训练不要求标准图块或自产资产；它沉淀的是命令、参数、图层、回读、审计和失败经验。
- 真实 CAD 声明仍需要 `CAD_PLAN` / 结构化意图、validate、dry-run、`CODEX_PREVIEW`、created handles 回读、审计和必要截图。

## 训练入口

普通训练仍从 `docs/training/README.md` 和 `docs/planning/任务清单.md` 进入。不同的是，后续每轮训练先问：

```text
这是 CAD Designer Agent 的哪一阶段课程？
```

若是第一阶段，优先选择基础 CAD 操作课程；若进入家装对象案例，也要说明它依赖哪些基础课程。
